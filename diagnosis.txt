# ARIA NEXUS — Wake Word Diagnosis (Remote Device Stream)
# Date: 2026-06-28

## Root Cause 1: Broken resampling in frontend/application/js/wakelistener.js

File: frontend/application/js/wakelistener.js
Function: startStream() (lines 225-269)

Line 238:  sInRate = sCtx.sampleRate || 48000;
           -> Captures device's native rate (44100 Hz on many phones/Android).

Line 243:  var ratio = sInRate / 16000;
           -> e.g. 44100/16000 = 2.75625 (fractional step).

Line 247:  for (var i = 0; i < input.length; i += ratio)
           -> Loop increments by a fractional value.

Line 248:  sResample.push(input[Math.floor(i)] || 0);
           -> Three bugs:
             (a) No anti-aliasing low-pass filter at 8 kHz
                 -> energy above 8 kHz aliases into the passband,
                   corrupting openWakeWord mel spectrogram features.
             (b) Nearest-neighbor pick (Math.floor) instead of interpolation
                 -> fraction step makes output sample positions jittery.
             (c) No phase compensation for fractional decimation ratio.
           -> Feeds openWakeWord a distorted/wrong-rate signal;
             scores never cross WAKE_THRESHOLD (0.5).

Fix:
  Primary: Create dedicated 16 kHz AudioContext:
           new AudioContext({ sampleRate: 16000 })
           -> e.inputBuffer.getChannelData(0) is already 16 kHz.
  Fallback: Linear interpolation + low-pass pre-filter.
  Keep ScriptProcessorNode (AudioWorklet too complex for this).
